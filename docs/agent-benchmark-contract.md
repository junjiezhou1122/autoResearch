# 研究 agent 的 benchmark 接入约定

本约定来自 2026-10-09 用户对 AI Idea Bench 接入方式的明确纠正。实验要回答的问题是，将 benchmark 的任务交给我们的 claude-research 研究 agent 后，实际交付效果如何。

## 保留官方任务

官方提供什么 instruction 和 input，就使用什么。保留任务目标、证据内容、附件、数据表示、允许的资源和输出要求。不能把不同任务统一改写为 hypothesis，也不能自行删减字段或增加研究方法提示。

先区分作者原始运行流程与本地 adapter。原始模型收到摘要时，不能把全文输入称为原始输入。使用本地 adapter 的导出数据时，明确记录这一入口及其与作者流程的差异。

官方 task ID、结果保存外壳和评分材料由接入程序处理。隐藏目标答案、评分 rubric 和真实标签不得传给生成 agent。官方生成 instruction 自带的自评分字段属于任务输出，不能与隐藏评分材料混淆。

## 固定通用 agent

claude-research 是隔离配置的 Claude Code 启动器。它关闭 CLAUDE.md 自动发现，因此运行时必须显式加载[通用研究说明](research-agent.md)与 autoresearch 插件，并保存实际启动参数、插件清单、工具清单和版本。

通用说明只定义自主完成任务、按需使用研究技能、遵守任务的证据与工具范围，以及保持原任务输出要求。具体的 hypothesis、JSON、实验方案、报告或字数由任务 instruction 决定。

Skills condition 通过原生 /autoresearch:research-mode 启动，不额外添加固定 leaf 顺序、调用次数、hypothesis 完成提示或中间确认回合。15 个 leaf 的最小方法内容保持不变。

工具配置按官方任务可用资源确定并记录。任何缩减或扩展都必须在报告中说明，不能将受限工具运行称为完整工具能力验证。不要将“快速跑”自行解释成截断研究交付的短截止时间。官方有运行限制时按官方限制；否则减少样本、控制并发，并记录实际耗时。

## adapter 只做接口转换

adapter 负责原始任务输入的传入、附件映射、最终结果收集、官方解析、保存结构和官方评分。尽量复用官方代码，保留来源与哈希。

作者生成器的内部模型策略由我们的 agent 替代。官方强制任务协议仍应保留。若对照组复现作者的固定反思循环，单独标记该流程；不能把它叠加到自主 Skills condition，再称为单次自然任务。

保留原始回复。按官方解析器正常提取的 fenced JSON 不属于科研内容修复。未经官方允许的字段填补、结构修复和人工内容修改另行记录，不能算作原始正常交付。

## 先验证评分，再运行

生成前，用实际评分路线验证官方各类评分请求能返回正常结束、非空最终 content 和完整评分 schema。能连接 API 不等于评分预检通过。

只接受最终 content 中的有效评分，不把 reasoning_content 当最终答案。响应缺失、截断、schema 错误或依赖不可用都记录为评分失败。未得到全部任务分数时，完整均分保持不可用。

生成完成、任务交付和评分完成是三个独立状态。评分阻塞时报告“生成已完成，质量评估未完成”，不能用生成成功代替完整评估。

## 结果解释

每次创建新的结果目录，保存任务来源、输入和提示哈希、agent 配置、原始 stream、实际 Skill 调用、输出、评分请求与最终响应、耗时和 token。保留所有选定任务及失败的分母。

小样本和单次运行只提供探索性反馈。任务提示、数据表示、工具配置或 agent 协议变化时，不能将新旧结果差异直接归因于 Skills。历史结果保留，不覆盖或恢复已撤回的无效均分。
